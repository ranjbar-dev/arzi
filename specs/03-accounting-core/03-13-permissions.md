## 13. Permissions

### 13.1 Mechanism

Two independent layers.

**(a) The supervisor flag.** `Password.Supervisor` (0/1). Read at login into `Dm.Admin`
(`Dmu.pas:109`, `:744`). Gates:

| Feature | Cite |
|---|---|
| Admin screen (`B_Admin`) | `Mainu.pas:957` |
| Close the books (`B_Enteghal1`) | `Mainu.pas:958` |
| `B_Enteghal2` (unused button) | `Mainu.pas:959` |
| Year-end carry-forward (`B_Enteghal3`) | `Mainu.pas:960` |
| Account lock/unlock button on `SNewu` | `SNewu.pas:95` (`B_Lock.Visible := Dm.Admin`) |
| Bypass of every account lock | `Dmu.pas:923-924` |
| Bypass of every voucher lock | `Dmu.pas:985-986` |
| Bypass of the party-account lock | `Dmu.pas:970-971` |

**(b) Fine-grained numeric permissions.** Table `Pass_Config (P_User, P_ID, P_DESC)`. A row's
*presence* grants the permission:

```sql
-- Dmu.pas:1557-1558
 Select * From Pass_Config where P_User= <userId>
 and P_ID= <key>
```

`Dm.IsEnabel(UserID, Key) : Boolean` returns `RecordCount > 0` (`Dmu.pas:1552-1562`). **Note there is
no caching** — every button-visibility evaluation is a round-trip.

Maintained by `Admin.pas` (`TAdminF`). The editor is generated by reflection: it scans components
named `C1000`..`C3000` and treats each as a permission checkbox (`Admin.pas:204-214` save,
`:220-229` load):

```pascal
// Admin.pas:192-214 -- save
   Q1.SQL.Add(' Delete Pass_Config Where P_User = :UID ');
   Q1.Parameters.ParamByName('UID').Value := UserID;
   Q1.ExecSQL;
   Q1.SQL.Add(' Insert Pass_Config (P_User, P_ID, P_DESC ) Values ( :User, :ID, :Desc)' );
  for i := 1000 to 3000 do
  if ( FindComponent('C' + IntToStr(i)) <> nil ) then
  Begin
     N := Copy( (FindComponent('C'+IntToStr(i)) as TsCheckBox).Name, 2, 4);
     Q1.Parameters.ParamByName('ID').Value := N;
     Q1.Parameters.ParamByName('Desc').Value := (FindComponent(...) as TsCheckBox).Caption;
     if (FindComponent(...) as TsCheckBox).Checked then Q1.execSQl;
  End;
```

Delete-all-then-reinsert, **not in a transaction** — a crash mid-save leaves the user with no
permissions.

User management, also on `Admin.pas`, via a popup menu on the user grid:

| Menu item | Persian | English | Behaviour |
|---|---|---|---|
| `N_User` | کاربر جدید | New user | Prompt `'نام کاربر'` ("user name"); `UserCode := max+1`, `Enabled := 1`, `supervisor := 0`. Success `'کاربر جدید اضافه شد'` ("new user added"). `Admin.pas:165-183` |
| `E_User` | — | Toggle enabled | Flips `Password.Enabled`; `'تغییرات اعمال شد'` ("changes applied"). `Admin.pas:257-267` |
| `C_Name` | — | Rename user | Prompt `'تغيير نام کاربر'` / `'نام جديد'`; `'نام کاربر تغییر کرد'` ("the user name was changed"). `Admin.pas:269-279` |
| `C_Pass` | — | Change password | Prompt `'رمز جدید'`; `'رمز تغییر کرد'` ("the password was changed"). `Admin.pas:281-292` |

**The password is stored in plain text** (`Admin.pas:289`: `Password.FieldByName('password').asstring := st`).
Must be replaced with a proper hash in the rebuild.

Save confirmation: `'تغییرات ذخیره شد'` ("the changes were saved") — `Admin.pas:216`.
