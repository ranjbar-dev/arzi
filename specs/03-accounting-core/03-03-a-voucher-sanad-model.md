## 3. The voucher (Sanad) model

### 3.1 Two tables: header and lines

| Table | Role | Proposed name |
|---|---|---|
| `DMoein` | Voucher **header** (one row per voucher) | `vouchers` |
| `Moein` | Voucher **lines** / articles (one row per debit or credit line) | `voucher_lines` |

Critically, **`Moein` is the system of record and `DMoein` is derived.** `DMoein` was retrofitted:
`Mainu.pas:1027-1035` contains the one-off backfill script as a comment:

```sql
-- Run to make DMoein in firt time
insert DMoein( DM_Sanad, DM_Atf, DM_Date, DM_Coid, DM_Tbed, DM_TBes, DM_Count, DM_Desc, DM_MUser, DM_MDate)
Select M_Sanad as DM_Sanad, 0 as DM_ATf, Min(M_Date) As DM_Date, Min(M_Coid) as DM_Coid
       , Sum(M_Bed) As DM_TBed, Sum(M_Bes) As DM_TBes, Count(*) As DM_Count, Min(Article) As DM_Desc
       , min(M_User) As DM_MUser, Min(M_Time) As DM_MDate
From moein
Group by M_Sanad
```

Consequences the rebuild must handle:
- Every screen tolerates a voucher that exists in `Moein` but not in `DMoein`. `SanadEditU.S_OpenClick`
  (`SanadEditU.pas:868-887`) explicitly checks both and loads whichever is present.
- The header's `DM_TBed`, `DM_TBes`, `DM_Count` are **caches** that can drift. Two routines rebuild
  them: `Dm.DMoein_Make` and `Dm.Dmoein_UpdateMab` (§3.5).
- `DM_Tx` is duplicated onto every line as `M_Tx`. Both are updated in the same transaction by every
  state transition (§3.6), but they can disagree if a line is inserted after a transition.

### 3.2 `DMoein` — header columns

From `SanadViewU.pas:32-45` and `SanadViewU.dfm:1313-1376`:

| Column | Type | Meaning | Proposed name |
|---|---|---|---|
| `DM_SSN` | `int identity` PK | Surrogate key | `id` |
| `DM_Sanad` | `int` | **Voucher number** — the business key, unique per `DM_Coid` | `voucher_number` |
| `DM_Coid` | `int` | Fiscal year (`Base.CO_ID`) | `fiscal_year_id` |
| `DM_Date` | `varchar(10)` | Jalali date `YYYY/MM/DD` | `date_jalali` |
| `DM_Desc` | `varchar(200)` | Voucher narration | `description` |
| `DM_TX` | `smallint` | **State**: 0 / 1 / 2 — see §3.6 | `status` |
| `DM_Lock` | `smallint` | 0/1 manual lock, independent of `DM_TX` | `is_locked` |
| `DM_TBed` | `bigint` | Cached sum of `M_Bed` | derived |
| `DM_TBes` | `bigint` | Cached sum of `M_Bes` | derived |
| `DM_Count` | `int` | Cached line count | derived |
| `DM_Kind` | `int` | **Document class**: `1` = Moein voucher, `2` = Rooznameh (journal) voucher | `voucher_kind` |
| `DM_Atf` | `int` | "عطف" — cross-reference / folio number. Displayed (`SanadViewU.dfm:541`) and printed, **never written by any code**. | `folio` (see §14) |
| `DM_MUser` | `int` | Creating user | `created_by` |
| `DM_MDate` | `datetime` | Creation timestamp | `created_at` |
| `DM_CUser` | `int` | Last-modifying user | `updated_by` |
| `DM_CDate` | `datetime` | Last-modification timestamp | `updated_at` |

**Note the reversed naming**: `DM_MUser`/`DM_MDate` are set on *insert* and `DM_CUser`/`DM_CDate` on
*update* — see `Dm.DMoein_Make` (`Dmu.pas:830-835`). "M" is `Made`, "C" is `Changed`. The rebuild
should rename to `created_*` / `updated_*` as above.

### 3.3 `Moein` — line columns

From `SanadEditU.pas:30-63`, `MoeinSearchU.pas:36-54`, `RooznamehViewU.dfm:1199-1218`:

| Column | Type | Meaning | Proposed name |
|---|---|---|---|
| `M_SSN` | `int identity` PK | Surrogate key | `id` |
| `M_COID` | `int` | Fiscal year | `fiscal_year_id` |
| `M_Sanad` | `int` | Voucher number (FK to `DMoein.DM_Sanad` within the same `COID`) | `voucher_number` |
| `M_Date` | `varchar(10)` | Jalali date, **copied from the header onto every line** | derived |
| `M_Bed` | `bigint` | Debit amount | `debit` |
| `M_Bes` | `bigint` | Credit amount | `credit` |
| `M_Ted` | `decimal` | Quantity/measure — label `'تعداد/مقدار:'` ("count/quantity", `EditArticleMoeinU.dfm:116`). Statistical, not part of balancing. | `quantity` |
| `Article` | `varchar` | **Line narration.** Note: no `M_` prefix. | `description` |
| `M_Tx` | `int` | State, mirror of `DM_TX` | derived from header |
| `M_Ko`, `M_Mo`, `M_Ta1`, `M_Ta2` | `int` | Account code tuple — **denormalised copy** of the `Sarfasl` tuple | derived from `account_id` |
| `M_Code` | `int` | **FK to `Sarfasl.S_SSN`** — the authoritative account reference | `account_id` |
| `M_Id` | `int` | **Source-system marker.** `0` = manual. Non-zero ⇒ generated by a subsystem; the line becomes read-only in the voucher editor. See §3.4. | `source_kind` |
| `M_Link` | `int` | **FK to the source document's primary key** in the originating subsystem. `0` for manual lines. | `source_id` |
| `M_User` | `int` | Creating user | `created_by` |
| `M_Kind` | `smallint` | Document class: `1` = Moein voucher line, `2` = Rooznameh line | `voucher_kind` |
| `M_time` | `datetime` | Insert timestamp (`GetDate()`) | `created_at` |

**Redundancy to resolve in the rebuild:** `M_Code` and `(M_Ko, M_Mo, M_Ta1, M_Ta2)` describe the same
account. The generators write `M_Code` first and then back-fill the tuple with a join
(`MakeSanadU.pas:112-114`, `NewFinalu.pas:220-222`). Keep `account_id` only; expose the tuple as a
view.

### 3.4 `M_Id` — the source-system marker

`M_Id` ranges are documented by the classifier in `MergeSanad.pas:206-234`:

```pascal
      I0 := QS.FieldByName('M_Id').AsInteger;
      if I0=0 then _ID0:=1;                    // دستی
      if (I0>0) and (I0<10) then _ID1:=1;      // فروش.
      if (I0>20) and (I0<30) then _ID2:=1;     // خزانه
      if (I0>10) and (I0<20) then _ID2:=1;     // پسته
```

and the labels assigned from them (`MergeSanad.pas:215-234`):

| `M_Id` range | Persian | English | Tag |
|---|---|---|---|
| `0` | سند دستی | Manual voucher | 0 |
| `1..9` | فروش انبار | Inventory sales | 1 |
| `11..19` | عملیات انبار پسته | Pistachio inventory operations | 3 (never reached — see below) |
| `21..29` | خزانه | Treasury | 2 |
| `31..39` | (inventory documents) | Inventory document postings — see §6 | — |

**Bug (do not port):** the `11..19` branch assigns `_ID2` (treasury) rather than `_ID3`, so the
`_ID3` label `'عملیات انبار پسته'` (`MergeSanad.pas:232`) is dead. Also, `_ID0.._ID3` are
uninitialised local variables — Delphi does not zero locals, so this classifier reads garbage when no
matching branch fires. The rebuild must classify deterministically.

Concrete `M_Id` values written by the inventory generator (`MakeSanadU.pas`):

| `M_Id` | Source | Set at |
|---|---|---|
| `31` | Opening stock (موجودی اول دوره) | `MakeSanadU.pas:206` |
| `32` | Purchase / goods receipt (خرید مواد و کالا) | `MakeSanadU.pas:341` |
| `33` | Sale (فروش) | `MakeSanadU.pas:610` |
| `35` | Sales return (برگشت از فروش) | `MakeSanadU.pas:476` |

Values 34, 36–39 are reserved (the delete statement covers `31..39`, `MakeSanadU.pas:85`).

**Effect of `M_Id > 0`:** the line is immutable from the accounting UI.

| Action | Guard | Persian message | English | Cite |
|---|---|---|---|---|
| Delete line in voucher editor | `M_Id > 0` | `'  از اینجا حذف امکان پذیر نیست  '` | "Deletion is not possible from here" | `SanadEditU.pas:1005` |
| Edit line in voucher editor | `M_Id > 0` | `'  از اینجا اصلاح امکان پذیر نیست  '` | "Editing is not possible from here" | `SanadEditU.pas:1020` |
| Edit line (legacy screen) | `M_id > 0` | `'اجازه اصلاح سند از اينجا وجود ندارد'` + `'از برنامه هاي جانبي استفاده شود'` | "You are not permitted to edit the voucher from here" / "Use the auxiliary programs" | `SanadMoeinu.pas:350` |
| Delete line by id | `Max(M_ID) > 0` | `'اجازه حذف آرتيکل از اينجا وجود ندارد'` + `'از برنامه هاي جانبي استفاده شود'` | "You are not permitted to delete the article from here" / "Use the auxiliary programs" | `Dmu.pas:1355` |
| Delete whole voucher | `Max(M_Id) > 0` | `'  سند از اینجا قابل حذف نیست از برنامه های جانبی استفاده کنید '` | "The voucher cannot be deleted from here, use the auxiliary programs" | `SanadViewU.pas:241` |
| Delete whole voucher (`Dm`) | `Max(M_ID) > 0` | `'سند غير قابل حذف است '` | "The voucher is not deletable" | `Dmu.pas:1310` |
| Copy voucher | `Max(M_link) > 0` | `'      فقط اسناد صادره دستی قابل کپی شدن هستند      '` | "Only manually issued vouchers can be copied" | `SanadViewU.pas:672` |
| Add to voucher (closing screen) | `M_ID > 0` | `'  امکان افزودن به این سند را ندارید  '` | "You cannot add to this voucher" | `NewFinalu.pas:112` |

Additionally, **the voucher save routine never touches generated lines**. `SanadEditU.B_SaveClick`
deletes only manual lines before re-inserting:

```sql
-- SanadEditU.pas:618-620
  Delete moein Where M_Sanad=<n>
    and M_Coid=<coid>
   and M_Link=0 and M_Id=0
```

and re-inserts only rows where `M_ID = 0` (`SanadEditU.pas:634`). Generated lines survive an edit
untouched. This is the core immutability guarantee — preserve it exactly.
